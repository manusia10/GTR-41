# Ai Bot Day 2

## สรุปงาน: ตั้งราคาจากข้อมูลผู้ซื้อ และขายให้หมด

Branch: `feat/buyer-aware-pricing`

### ปัญหาที่เจอ
- เกม sandbox ขายได้แค่ 600 จาก 1,260 กก. ข้อเสนอโดน ABOVE_LIMIT/OUTBID บ่อย และ round capacity นับ กก. ที่ "เสนอ" ทำให้ข้อเสนอที่ไม่ขายเสียโควตาไปเปล่าๆ
- บางรอบ agent ไม่เสนอเลย และไม่บอกเหตุผล
- prompt ของ LLM กรณีหนักที่สุด (ท้ายเกม 54 ตัวเลือก) ยาวเกิน 8,192 token ของ gateway → gateway error แล้วต้องใช้กฎแทนทั้งรอบ

### สิ่งที่ทำ

**1. ตั้งราคาจากข้อมูลผู้ซื้อ (`pricing.py` ไฟล์ใหม่)**
- เรียนรู้เพดานลับของผู้ซื้อแต่ละรายจากผลรอบก่อน: ACCEPTED/PARTIAL/OUTBID = ผ่านเพดาน, ABOVE_LIMIT = เกินเพดาน
- เก็บเพดานแยกตามคู่ (ผู้ซื้อ, ล็อต) ก่อน → ผู้ซื้อ → ประเภทผู้ซื้อ (TV ที่เราประเมินแต่ละล็อตคลาดไม่เท่ากัน)
- ใช้ `market_summary` ดูอัตราซื้อได้ (fill rate): ผู้ซื้อที่ขาดของ (<90%) ไม่ต้องสู้ราคา → ตั้งใกล้เพดาน · ผู้ซื้อที่แข่งดุ → ตั้งต่ำกว่าราคาที่เคยแพ้
- ใช้ผลแค่ 5 รอบล่าสุด เผื่อผู้ซื้อเปลี่ยนนิสัย

**2. ขายให้หมดด้วยราคาสูงสุด (`strategy.py`)**
- ความเร่ง (urgency) = กก. ที่ยังไม่ขาย ÷ (โควตาต่อรอบ × รอบที่เหลือ)
  - ต่ำกว่า 0.7 → ตั้งราคาใกล้เพดาน · 0.7–1.0 → ค่อยๆ ลดหาราคาที่เคยขายได้ (ยังขยับขึ้นทีละ +0.005) · รอบสุดท้าย = เร่งเต็มที่
- จัดลำดับข้อเสนอตาม ราคา × โอกาสขายได้ เพื่อใช้โควตากับข้อเสนอที่น่าจะขายได้ก่อน
- เพิ่มปริมาณที่เสนอเมื่อตามหลังแผน
- guard ไม่ให้ LLM ตั้งเกินราคาแนะนำ +0.03 และต้องต่ำกว่าเพดาน/ราคาที่เคยแพ้คู่แข่งเสมอ

**3. รอบที่ไม่เสนอ**
- ล็อตที่ไม่มี RFQ ไหนรับได้ (เช่นเกรด REJECT defect 20%) ไม่ถูกนับในความเร่งอีกต่อไป เดิมทำให้ agent ลดราคาล็อตอื่นเกินจำเป็น
- เสนอล็อตที่เกินสเปกนิดเดียว (stretch: defect +1.0pp, ความชื้น +0.4pp, screen −1) เพื่อใช้โควตาที่เหลือ เพราะผู้ซื้อตรวจคุณภาพจริง ไม่ใช่ผลวัดตัวอย่าง
- มี event `no_offers` บอกเหตุผลบนหน้าจอ

**4. ลด token ของ prompt ให้ไม่เกินที่ gateway รับได้ (ตามสไลด์วันที่ 18 หน้า 14)**
- ตารางตัวเลือกแบบย่อ: หัวคอลัมน์ครั้งเดียว ข้อมูลผู้ซื้อเขียนครั้งเดียว (`B1`, `B2`, …) ส่งไม่เกิน 24 ตัวเลือกที่ดีที่สุด และตัดแถวเพิ่มเองถ้ายังยาวเกิน
- วัดจริงบน gateway (กรณีหนักสุด): prompt **เกิน 8,192 → ~2,117 token** (รวมคำตอบ ~3,617 / 8,192)
- LLM จริงตอบใน 2.8 วินาที และใช้โควตาครบ

**5. อื่นๆ**
- `memory.py` บันทึกชื่อผู้ซื้อของแต่ละข้อเสนอ และสรุปประวัติแยกตามผู้ซื้อ
- `.env.example` ชี้ไปที่ตลาดและ LLM gateway ของงาน (key เป็นค่าตัวอย่าง ไม่มี key จริง)
